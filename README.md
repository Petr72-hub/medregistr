# МедРегистр

PyQt6-приложение для паспортных данных, анализов, календаря терапии и обеспеченности препаратами.

## Запуск (Windows / Python 3.12)

1. `python -m venv .venv`
2. `.venv\Scripts\python -m pip install -r requirements.txt`
3. `.venv\Scripts\python bot.py`

Для своей БД: `$env:MEDREGISTR_DB = "C:\MedRegister\children.db"`.
По умолчанию выбирается корневая children.db, затем существующая dist/children.db. Вложения — files рядом с БД; старые корневые files также доступны. Перед миграциями создаётся резервная копия средствами SQLite. Старые таблицы сохраняются. Источник bot.py продолжает medapp.py → meddapp.py; старые EXE в dist не включают эту версию.

## Терапия и склад

Из списка пациентов откройте «План терапии». Выберите препарат, индукцию с последующей поддержкой либо только поддержку, вес, назначенную дозу и интервал. Индукция инфликсимаба/ведолизумаба: дни 0,14,42; адалимумаба: 0,14. Веса индукционных строк редактируются отдельно. Первая поддержка рассчитывается от окончания индукции; дату можно изменить. План строится по реальным датам на следующие 12 месяцев (конечная дата включена).

Сохранённый план резервирует препарат. «Выдано» с фактической датой списывает целые флаконы/шприцы один раз. Дозу 125 мг при форме 100 мг обеспечивают 2 флакона. Плановая доза и выданное количество различаются. Выдача при нехватке фактического остатка или будущей фактической датой отклоняется.

Дополнительное введение можно добавить со сдвигом следующих регулярных дат или без него. Изменение веса действует с указанной даты на ещё не выданные события. Замена будущего плана сохраняет историю. Отмена освобождает резерв. Просроченный невыданный план остаётся в резерве.

«Аптека и прогноз»: поступления, резерв всех детей, страховой запас, остаток после плана, свободное сверх страхового, закупка и первая дата физического дефицита. Закупка учитывает минимальный остаток по всему периоду: более позднее поступление не скрывает более раннюю нехватку. Будущие поступления учитываются только в свою дату. Страховой запас задаётся отдельно в единицах препарата.

Старый журнал therapy доступен отдельной вкладкой только для чтения. Его записи учитываются по датам, без автоматического размножения старой схемы на год; будущие старые записи отмечаются для проверки. Новые годовые назначения нужно явно создать в плане, чтобы не получить дубли.

## Согласованные правила расчёта

- Инфликсимаб: форма 100 мг; индукция 5 мг/кг; поддержка 5 либо 10 мг/кг, интервал 4/6/8 недель.
- Ведолизумаб: форма 300 мг; индукция при весе <30 кг — 10 мг/кг, при >=30 кг — 5 мг/кг; поддержку 5/10 мг/кг и интервал 4/8 недель выбирает врач.
- Адалимумаб: форма 40 мг; индукция при >=40 кг — 160/80 мг, ниже — 80/40 мг. Поддержка при болезни Крона: фиксированные 20/40 мг на введение, интервал 1/2 недели. Поддержка при ЯК пока недоступна по согласованному локальному объёму проекта.
- Столбцы O/P исходной таблицы исключены. Возрастные ограничения и максимальные дозы не выдумываются: программа рассчитывает выбранную врачом схему, а не выбирает лечение.

## Проверки и дизайн

`.venv\Scripts\python -m pip install -r requirements-dev.txt`

`.venv\Scripts\python -m pytest -q`

Тесты используют временные БД и синтетические данные. Исходная dist/children.db пуста; её контрольная сумма сохранена. Реальную заполненную рабочую БД следует открывать сначала на копии.

Дизайн: Framed sheet (design-taste-frontend, seed1980516590), светлая зелёно-серая рамка, белая рабочая область, Segoe UI. Веб-инспектор неприменим к native Qt: проверка выполняется по рендерам реальных виджетов. Демонстрационные пациенты в изображениях не записываются в рабочую БД.

Ветка feat/patient-passport-laboratory, PR #1. Слияние в main только после подтверждения владельца.
