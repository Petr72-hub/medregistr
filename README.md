# МедРегистр

Приложение PyQt6 для детской гастроэнтерологии. Рабочий исходник — `bot.py`:
`medapp.py` (92f1259) → `meddapp.py` (6fa35f6) → `bot.py` (96ef6dc).

## Запуск из исходников (Windows)

1. Установить Python 3.12.
2. В папке проекта: `python -m venv .venv`.
3. Установить зависимости: `.venv\Scripts\python -m pip install -r requirements.txt`.
4. Запустить: `.venv\Scripts\python bot.py`.

Для своей базы можно задать в PowerShell:
`$env:MEDREGISTR_DB = "C:\MedRegister\children.db"`.
Без настройки используется children.db рядом с программой; при запуске исходников
и отсутствии корневой базы — существующая dist/children.db. Файлы вложений хранятся
в каталоге files рядом с выбранной БД. База в репозитории пуста.
Имеющиеся EXE — старые сборки; они не включают изменения этой ветки.

## Совместимость данных

Перед изменением старой схемы создаётся резервная копия средствами SQLite.
Старые таблицы и неизвестные столбцы сохраняются; поддержаны схемы medapp.py,
meddapp.py и bot.py. Паспортные поля district/pediatrician/is_disabled переносятся
в соответствующие поля текущей формы. Старые name/result и analysis_headers/details
доступны через новый интерфейс без удаления исходных таблиц.
Вложения копируются только после подтверждения сохранения, с уникальными именами.
Старые неизвестные показатели и повреждённые записи не удаляются автоматически.

## Проверки

`.venv\Scripts\python -m pip install -r requirements-dev.txt`

`.venv\Scripts\python -m pytest -q`

Тесты работают с временными БД и искусственными данными. Рабочую базу не используют.
Каталог анализов содержит 14 показателей ОАК, 17 ОАМ и 17 биохимии; названия и единицы
сохранены согласно исходному ТЗ, без автоматической интерпретации результатов.

## Расчёты препаратов — уточнение требований

Расчёт потребности к дате является основным критерием приёмки. Правила из
preparaty.xlsx требуют уточнения границ веса, графиков, округления упаковок,
учёта фактических введений и возрастных ограничений. Существующая логика терапии
сохранена, но ещё не прошла приёмку по этим требованиям. Прохождение тестов
паспортной части и анализов не подтверждает корректность медицинских расчётов.

## Организация разработки

Архитектура и QA, SQLite и PyQt6 проверяются отдельными субагентами.
Координатор выполняет интеграционную проверку и сверку медицинских полей.
Изменения готовятся в feat/patient-passport-laboratory; слияние в main — только
после подтверждения владельца.
